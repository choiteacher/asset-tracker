# 단계별 명세

> 각 단계 시작 시 해당 단계를 읽고 파일 구조·구현 계획을 짧게 요약한 뒤 구현한다.
> 진행 규칙과 공통 원칙은 `CLAUDE.md` 참조.

---

## 1단계: 프로젝트 세팅 + 비밀번호 대문 + 암호화 저장 + 배포

### [프로젝트 세팅]
- Vite + React + TypeScript, HashRouter, Vitest 설정
- vite.config의 base는 저장소 이름으로 설정
- .github/workflows에 GitHub Pages 자동 배포(Actions) 포함. main 브랜치 push 시 빌드/배포
- .gitignore 정리(백업 파일, .env 포함)

### [비밀번호 대문 — 반드시 실제 암호화 방식]
- 최초 진입: 비밀번호 설정 화면(확인 입력, 최소 길이 안내, 간단한 강도 표시)
- 이후 진입: 비밀번호 입력 화면. 올바르게 입력해야만 복호화되어 메인 화면 진입
- WebCrypto: PBKDF2(SHA-256, 반복 300,000회 이상, 랜덤 salt)로 키 유도, AES-GCM 암호화, 저장할 때마다 새 랜덤 IV
- 비밀번호와 키는 어디에도 저장하지 말고 메모리에만 유지. 저장되는 것은 암호문, salt, IV, 버전 정보뿐
- 비밀번호 검증은 복호화 성공 여부로 판단
- 자동 잠금: 무조작 N분(기본 10분, 설정 가능) 후 잠금. 잠금 시 메모리의 키와 데이터 제거
- 실패 시 점진적 지연(시도 횟수에 따라 대기 시간 증가)
- 비밀번호 변경 기능(기존 비밀번호 확인 후 전체 재암호화)
- "비밀번호를 잊으면 복구할 수 없습니다" 안내 문구를 설정 화면에 표시

### [저장 구조]
- StorageAdapter 인터페이스(load/save/export/import) 정의, IndexedDB 구현체 작성
- 앱 전체 데이터를 하나의 JSON 객체로 직렬화해 통째로 암호화 저장(스키마 버전 필드 포함)
- 암호화 백업 내보내기(.json 다운로드)/가져오기. 백업 파일도 암호문이며, 가져올 때 비밀번호로 검증
- 마지막 백업 일시 기록, 30일 이상 백업이 없으면 메인 화면에 알림

### [산출물]
프로젝트 구조, 대문+암호화 모듈, 빈 메인 화면 + 설정 화면(비밀번호 변경, 자동 잠금 시간, 백업), 암호화/복호화 단위 테스트, GitHub Pages 배포 방법(PowerShell 기준, 저장소 연결과 Pages Source를 GitHub Actions로 설정하는 방법 포함), 파일별 역할 설명

## 2단계: 자산 등록 (입력 화면)

### [데이터 모델] (스키마 버전을 올리고 마이그레이션 고려)
공통: id, 상품명, 금융기관명, 메모, 유동/동결 구분(유형별 기본값 제안, 사용자 변경 가능), 동결 해제 예정일(선택), 평가/기준일
- 정기예금: 예치원금, 연이율(%), 가입일, 만기일, 이자 지급방식(만기일시/월지급), 과세유형
- 정기적금: 월납입액, 연이율(%), 가입일, 만기일, 납입일, 지금까지 납입 회차, 과세유형
- 청약저축: 현재 납입 총액, 월납입액, 연이율(%), 가입일, 기본 동결 처리
- 주식, 펀드: 평가금액(직접 입력), 평가 기준일
- 현금/입출금: 금액, 기준일

### [과세유형]
- 일반, 세금우대, 비과세, 2금융권 세금우대(상호금융 등) 4가지로 분리
- 설정 화면에 "세율 프리셋" 표를 만들어 유형별 세율을 수정 가능하게 한다. 초기값은 일반 15.4%(소득세 14% + 지방소득세 1.4%), 비과세 0%. 나머지 두 유형은 예시값을 넣되 "확인 필요 — 가입 상품 안내문 기준으로 수정" 경고 배지를 붙인다
- 2금융권 세금우대는 금융기관명과 별도 세율/한도 메모 필드를 둔다

### [UI]
- "자산 관리" 화면: 유형별 탭/필터, 목록, 추가/수정/삭제(삭제 전 확인)
- 입력 폼은 유형에 따라 필요한 항목만 표시, 입력 검증(음수, 만기<가입일 등)
- 목록 상단에 유동자산 합계/동결자산 합계(단순 원금 기준, 실시간 계산은 3단계)
- 메인 대시보드는 아직 만들지 말고 간단한 요약 카드만 둔다

### [테스트]
데이터 모델 검증 함수, 저장/불러오기 왕복 테스트

---

## 3단계: 이자·세금 계산 엔진 + 초 단위 실시간 메인 화면

### [계산 엔진 — UI와 분리된 순수 함수, 기준 시각을 인자로 받는다]
- 정기예금: 단리 기준 일할 계산으로 가입일~기준 시각까지 누적 이자(초 단위 환산). 만기 이후 이자 증가 중지
- 정기적금: 납입 회차별로 납입일부터 개별 이자를 계산해 합산(미래 회차 제외). 만기 이후 증가 중지
- 청약저축: 납입 총액과 연이율로 동일 방식 계산
- 주식/펀드/현금: 입력한 금액 그대로
- 세금: 상품의 과세유형 세율로 세전 이자에서 계산. 세후/세전 표시 전환 토글(기본 세후)
- 유형별(일반 vs 2금융 세금우대 vs 비과세) 누적 이자소득세를 따로 집계
- 실시간 표시는 값을 누적 증가시키지 말고, 매 프레임 Date.now() 기준 "현재 시각의 값"을 처음부터 다시 계산(오차 누적 방지). 갱신 주기 약 100ms
- 상품별 만기 도래 여부, 만기 시 예상 수령액(세후) 함수 제공

### [메인 대시보드(열람 화면)]
- 맨 위에 총 자산(순자산)을 크게, 소수점 첫째 자리까지 실시간 표시. 고정폭 숫자(tabular-nums)로 화면 흔들림 방지
- 그 아래 유동자산/동결자산 카드(각각 실시간), 부채 카드(4단계 전까지 0)
- 이자 증가 속도(초당/하루 증가액)
- 세금 현황 카드: 누적 이자, 누적 이자소득세, 유형별 구분
- 상품별 목록: 현재 평가액, 세전/세후 이자, 만기일, D-day
- 탭이 숨겨지면 갱신을 멈추고, 돌아오면 즉시 재계산
- 하단에 "추정치이며 실제 금액과 다를 수 있음" 문구

### [테스트]
고정 기준 시각으로 예금/적금/청약 이자, 세금, 만기 이후 동작 검증(가상 숫자). 검증 방식을 설명

---

## 4단계: 대출 등록 + 상환 계산 + 금융 Tip

### [대출 데이터]
대출명, 금융기관, 최초 대출금, 현재 잔액(기준일 포함), 연이율(%), 상환방식(원리금균등/원금균등/만기일시), 월 상환액(원리금균등은 자동 계산값과 비교해 직접 입력도 허용), 상환일, 시작일, 만기일, 중도상환수수료율(%)과 면제 시점(선택), 월 상환액을 자동 차감할 연결 현금 항목(선택)

### [계산]
- 방식별 상환 스케줄. 현재 잔액, 누적 납부 이자, 남은 이자 총액
- 대출 이자를 초 단위로 환산해 실시간 누적하고, 순자산 = 자산 − 대출 잔액 − 미납 누적 이자로 반영
- 월 상환일이 지나면 스케줄에 따라 잔액 감소. 연결 현금 항목이 있으면 그만큼 현금도 자동 차감해 순자산이 부풀지 않게 한다. 지정이 없으면 자동 차감하지 않고 대출 카드에 "월 상환액이 현금에서 빠지지 않는 설정" 경고 표시
- 완전 상환 예상 시기(년월)와 남은 개월 수
- 시뮬레이션: "월 상환액 +N원이면 N개월 단축·이자 N원 절감", "지금 N원 중도상환하면 단축 기간·절감 이자(수수료 반영)"

### [금융 Tip — 규칙 기반, 조건과 근거를 함께 표시]
- 대출 금리 > 보유 예적금 세후 금리일 때 유동자산 일부 중도상환 검토 Tip(중도상환수수료와 비상자금 확보를 반드시 함께 안내)
- 중도상환수수료 면제 시점이 가까우면 안내
- 만기 임박 예적금의 만기 수령액으로 대출을 줄이는 방안
- 유동자산 부족 가능성 경고
- 모든 Tip에 "투자 자문이 아닌 참고용" 문구, 계산 근거(어떤 숫자를 비교했는지)를 펼쳐볼 수 있게 한다

### [UI]
대출 관리 화면(등록/수정/삭제), 대시보드의 부채 카드/상환 현황 카드/Tip 카드, 대출 상세(상환 스케줄 표, 잔액 추이 그래프)

### [테스트]
방식별 스케줄, 완전 상환일, 중도상환 시뮬레이션, 순자산 반영 검증(가상 숫자)

## 5단계: 분양 D-day 대시보드

### [분양 일정 등록]
- 단지명(선택), 분양가, 지급 일정(계약금/중도금 회차/잔금 각각의 날짜와 금액 또는 비율), 분양 예정일(기본 내년 4월, 수정 가능)
- 중도금 대출 등은 4단계 대출 항목으로 등록하고 연결 가능하게 한다
- 상품별 "분양 시점 활용 가능 여부"와 "유동화 예정일" 설정(예: 청약저축, 만기 적금). 활용 가능 여부는 사용자가 판단해 입력

### [예측]
- 미래 특정 날짜의 예상 유동자산/동결자산/부채를 계산하는 함수(기준 시각 인자). 만기로 동결이 풀리는 자산, 매월 적금 납입, 대출 상환을 반영
- 각 지급일마다 "필요 금액 vs 예상 유동자산" 비교, 부족 시 부족액과 경고
- 분양 D-day 카드: 남은 일수, 분양 시점 예상 총자산, 필요 자금 대비 여유/부족
- 월별 예상 자산 추이 그래프(Recharts) 위에 계약금/중도금/잔금 시점 표시
- 월 추가 저축액/지출 변동을 가정해보는 임시 "만약에" 입력칸(저장하지 않음)

### [주의]
- 예측은 현재 입력 데이터 기반 추정이며 주식/펀드는 현재 평가금액으로 고정 가정함을 화면에 명시
- 청약저축 등 분양 제도 조건은 코드에 단정적으로 박지 말고 사용자 입력으로 처리

### [테스트]
미래 시점 예측, 부족 경고 판정 검증(가상 숫자)

## 6단계: 기록·그래프·알림·마무리

### [자산 기록(스냅샷)]
- 잠금 해제 후 앱을 열 때 오늘 날짜의 스냅샷이 없으면 순자산/유동/동결/부채를 하루 1회 기록(암호화 데이터 안에 저장). 데이터 등록/수정 시 "변경 내역"도 날짜와 함께 기록
- 월별/주별 순자산 추이 그래프, 유동/동결 구성 변화 그래프
- 자산 변화 기록 화면: 언제 어떤 항목을 바꿨는지 타임라인

### [알림(앱 내 표시)]
- 예적금 만기, 대출 상환일, 분양 지급일 D-day 목록을 대시보드 상단에 표시
- 백업 권장 알림(마지막 백업 후 30일 경과, 데이터 변경 후 백업 안 한 상태)

### [열람 모드]
- 대시보드 위주 "보기 모드"와 수정 가능한 "편집 모드" 구분, 편집 모드 진입 시 한 번 더 확인
- 금액 가리기 버튼(옆 사람 시선 대비): 숫자를 ••••로 가렸다가 클릭하면 표시

### [마무리]
- PWA(홈 화면 추가) 선택 적용: manifest와 아이콘. 서비스 워커 캐시에 자산 데이터가 들어가지 않는지 확인
- 보안 점검: 콘솔 로그, URL, 저장소에 자산 데이터가 노출되는 곳이 없는지 코드 전체 점검 결과 보고
- 접근성/가독성 점검, 큰 글씨, 다크 모드
- README: 설치, 배포, 백업/복구 절차, 한계(기기 간 동기화 없음, 비밀번호 분실 시 복구 불가, 추정치) 정리. README에 개인 데이터나 실제 금액은 쓰지 않는다
